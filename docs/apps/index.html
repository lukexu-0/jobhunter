Resume tailoring applications

The apps/ Bun workspace contains the local pipeline API and its Next.js review interface.

  • Pipeline service
  • Web interface

Prerequisites

The workspace declares Bun 1.3.14 with the web and pipeline workspaces. The pipeline doctor also requires the latexmk executable and Poppler’s pdfinfo, pdftotext, pdffonts, and pdftoppm. Use the provider-access controls in the web UI to connect the two application-owned OAuth accounts before processing a run; do not supply provider API keys.

Source: apps/package.json, apps/pipeline/src/system/doctor.ts, and apps/pipeline/src/auth/service.ts.

Install, develop, verify, and build

Run these commands from a repository checkout. They are the workspace scripts defined in apps/package.json.

cd apps && bun install
cd apps && bun run dev
cd apps && bun run test
cd apps && bun run typecheck
cd apps && bun run build

The development command starts the pipeline first, waits for its health endpoint for up to 30 seconds, and starts the web server only after the endpoint responds successfully. The test, typecheck, and build scripts run pipeline work before web work.

For focused operational checks, use the package scripts:

cd apps && bun run --cwd pipeline context:sync
cd apps && bun run --cwd pipeline context:sync -- --check
cd apps && bun run --cwd pipeline doctor

Ports and boundaries

Web
Next.js binds to 127.0.0.1:3456.
Pipeline
The Bun API binds to 127.0.0.1:3457 and serves versioned routes below /v1.
Browser API boundary
Next rewrites same-origin /api/pipeline/:path* to http://127.0.0.1:3457/v1/:path*; browser code therefore calls the web origin rather than the loopback API directly.

Sources: apps/web/package.json, apps/pipeline/src/index.ts, and apps/web/next.config.ts.

Directory map

  • apps/package.json — workspace declaration and aggregate scripts.
  • apps/scripts/dev.ts — coordinated development launcher and signal shutdown.
  • apps/pipeline/ — Bun API, worker, source-context index, SQLite stores, artifact handling, and package-local scripts. See Pipeline service.
  • apps/web/ — Next.js application, same-origin rewrite, dashboard, and run-review screen. See Web interface.

Startup and shutdown

  1. Start development with cd apps && bun run dev.
  2. Open http://127.0.0.1:3456; the pipeline health check is http://127.0.0.1:3457/v1/health.
  3. Use Ctrl+C (SIGINT) or send SIGTERM to the coordinated launcher. It signals the pipeline and web child processes; the pipeline stops its server and closes its application services.

Sources: apps/scripts/dev.ts, apps/pipeline/src/index.ts, and apps/pipeline/src/bootstrap.ts.

Troubleshooting and verification

Run cd apps && bun run --cwd pipeline doctor to receive bounded JSON checks for Bun, the context index, both OAuth providers, both model descriptors, latexmk, and the four Poppler tools. auth_absent and auth_expired are warnings, not doctor errors; an absent OAuth connection alone does not make the doctor exit nonzero. Missing system tools, stale or invalid context, invalid model descriptors, and invalid auth configuration are errors and make the report unsuccessful.

If context is stale, run cd apps && bun run --cwd pipeline context:sync, then repeat the doctor command. To check without changing the index, use cd apps && bun run --cwd pipeline context:sync -- --check; a stale check exits nonzero. For API availability, request /v1/health through the pipeline port or through the web rewrite.

Sources: apps/pipeline/scripts/doctor.ts, apps/pipeline/src/system/doctor.ts, apps/pipeline/scripts/context-sync.ts, and apps/pipeline/src/api/handler.ts.
