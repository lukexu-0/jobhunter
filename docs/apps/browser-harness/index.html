Browser harness

The browser harness is a local, human-reviewed application service. It exposes a bearer-protected session API and uses the pipeline’s optional internal Codex bridge rather than provider API keys.

  • Apps workspace
  • Pipeline Codex bridge

Scope and boundaries

The harness API creates and monitors browser-application sessions; it does not expose OpenAPI, Swagger UI, or ReDoc. The unauthenticated GET /healthz response is {"status":"ok"}. Every /v1/ route instead requires an exact Authorization: Bearer … value matching the configured token. Missing, malformed, and incorrect credentials all receive the same 401 {"code":"unauthorized","message":"Unauthorized"} response. Responses are Cache-Control: no-store, and the application does not add CORS headers.

Do not treat the harness API as a browser-facing cross-origin API or place its bearer token in client-side code. It is a local/internal control boundary; callers that need a browser UI should remain on a trusted local integration.

Sources: apps/browser-harness/src/browser_harness/api.py and apps/browser-harness/tests/test_api_models.py.

Configuration

Harness bearer token
The HarnessConfig.bearer_token value is required and must contain at least 32 characters. The harness sends that value as the bearer credential when it calls the pipeline bridge.
Pipeline URL
HarnessConfig.pipeline_url defaults to http://127.0.0.1:3457. It accepts only a loopback HTTP URL, without user information, query, or fragment. The bridge client further requires an origin only: no path, query, fragment, or remote host.
Harness listener settings
The configuration model defaults to port 8765 (valid range 1–65,535) and a 3,600-second session timeout. These are configuration values; the present source tree provides the FastAPI application factory, not a documented standalone launcher.
Browser connection
An optional CDP URL must be loopback HTTP with no credentials, query, or fragment. A CDP URL and a local Chrome executable are mutually exclusive. The default Chrome user-data directory is ~/.jobhunter/browser-harness/chrome.

The pipeline reads JOBHUNTER_HARNESS_TOKEN when it constructs its application. It must be at least 32 characters when set. Leave it unset to disable the bridge completely: the exact internal path responds with 404 NOT_FOUND, rather than revealing that authentication is available. Configure the same secret as the harness bearer token through the trusted local process environment; never include its value in commands, source, or documentation.

Internal Codex bridge

With JOBHUNTER_HARNESS_TOKEN configured, the pipeline exposes only GET and POST /v1/internal/browser-harness/codex. The pipeline itself binds to 127.0.0.1:3457. This exact internal route is dispatched before the pipeline’s public mutation-Origin policy, but it is independently protected by the shared bearer token; it is not a public pipeline API route.

GET checks that the application-owned openai-codex OAuth connection is present and returns only modelProvider (openai-codex), model (gpt-5.6-sol), reasoning (high), and oauth (connected). When the OAuth connection is unavailable, it returns 409 OAUTH_REQUIRED. Connect OpenAI Codex through the pipeline’s provider-access flow; this bridge neither accepts nor documents static provider API keys.

POST requires Content-Type: application/json and accepts only sessionId, systemPrompt, transcript, and optional outputSchema. sessionId must be a UUID; the system prompt is limited to 1 MiB UTF-8 and the transcript to 3 MiB UTF-8. The complete request body is limited to 4 MiB, including streamed bodies. An optional schema must be a strict object schema with properties, required keys, and additionalProperties: false. Invalid input receives 422 INVALID_REQUEST; a wrong media type receives 415 JSON_REQUIRED; and a request over 4 MiB receives 413 REQUEST_TOO_LARGE.

The bridge applies a 300-second deadline while reading the request and while resolving the model. Its completion contains the fixed provider, model, and reasoning metadata, an output object ({"type":"text","text":"…"} or {"type":"structured","value":{…}}), and nonnegative input, output, and total token counts. It requests high reasoning, disables model storage and tracing, allows no retries or parallel tool calls, and caps model output at 16,384 tokens. A structured request forces the single strict emit_browser_use_output tool. Timeout, OAuth, malformed-output, and provider failures use fixed public errors; raw prompts, transcripts, OAuth material, reasoning, and provider error bodies are not returned.

Session API

All routes in this table except /healthz require the harness bearer token. Validation failures are 422 with the sanitized invalid_request response; unexpected failures are 500 internal_error.

POST /v1/sessions
Accepts multipart form data and returns 202 with a starting session ID plus event and command URLs. Required uploads are personal_information and resume. It accepts repeated allow_domain values (at most 20), context uploads (at most 10), anecdote uploads (at most 20), and max_steps from 1 through 500 (default 100). A currently active session is reported as 409 session_active with its session ID.
GET /v1/sessions/{session_id}
Returns the sanitized session snapshot.
GET /v1/sessions/{session_id}/events
Streams server-sent events as text/event-stream. A nonnegative integer Last-Event-ID is accepted for resumption; a negative or noninteger value is rejected.
POST /v1/sessions/{session_id}/commands
Accepts one strict discriminated command and returns 202: continue, approve_origin with an exact origin, revise with 1–20,000 trimmed characters of context, ready, or cancel.
DELETE /v1/sessions/{session_id}
Deletes the session and returns 204.

Job URLs must be absolute HTTP(S), may not contain user information or fragments, and require HTTPS unless they are loopback. Approved origins are exact canonical origins: HTTPS is required except for a loopback fixture; paths, queries, fragments, credentials, wildcards, and duplicates are rejected. When a session is awaiting a new origin, use approve_origin only for the exact requested origin.

Sources: apps/browser-harness/src/browser_harness/api.py, apps/browser-harness/src/browser_harness/models.py, and apps/browser-harness/tests/test_api_models.py.

Uploads and public artifacts

The API’s count and step controls are the request boundary; the present route does not declare a byte-size limit for multipart uploads. Candidate-context loading separately requires a nonempty text-extractable resume of at most 100,000 characters, text uploads of at most 100,000 characters each, and no more than 250,000 combined resume, profile, context, and anecdote characters. Invalid candidate context is exposed only as 422 invalid_request.

Candidate evidence is attributed by safe basename. Explicit direct personal values are intentionally excluded from the rendered evidence; the system instead creates domain-scoped sensitive placeholders from those explicit fields for the approved origins. Public snapshots and application results expose field labels, types, and a value_present flag, not field values. Public file names must be safe basenames (1–255 characters, with no path separators or control characters) and lists are bounded to 20 files. Public URLs remove credentials, query strings, and fragments before serialization. The application result hard-codes submit_attempted to false, retaining the human submission step.

Focused commands

The Python project declares Python 3.12, a dev extra containing pytest and pytest-asyncio, and tests as its pytest test path. After installing the project and its dev extra in the intended Python 3.12 environment, run either focused test module from apps/browser-harness:

python -m pytest tests/test_api_models.py
python -m pytest tests/test_pipeline_model.py

The bridge’s focused pipeline verification is:

cd apps/pipeline && bun test test/browser-harness-codex.test.ts

These are test commands supported by the declared pytest and Bun test configuration. No standalone harness start command is documented because the package’s configured console-script target is not present in this source tree.
