Resume tailoring pipeline

Loopback Bun API, single-worker resume-tailoring workflow, local context index, OAuth-only model access, and reviewed artifacts.

  • Apps workspace
  • Web interface

Configuration and data stores

The package is @jobhunter/pipeline. Its scripts are dev, build, start, typecheck, test, context:sync, and doctor. The API listens only on 127.0.0.1:3457; its default allowed mutation origin is http://127.0.0.1:3456, overridable with JOBHUNTER_WEB_ORIGIN.

Three SQLite databases are deliberately separate: pipeline state at apps/pipeline/data/state/pipeline.sqlite, context index at apps/pipeline/data/context/context.sqlite, and OAuth storage at apps/pipeline/data/oauth/auth.sqlite. The state and context databases use WAL, foreign keys, and a 5-second busy timeout. Context and OAuth directories are created with mode 0700; the context and OAuth database files are set to 0600. Run inputs and attempt artifacts are stored beneath apps/pipeline/data/runs.

Sources: package.json, src/index.ts, src/bootstrap.ts, src/db/database.ts, src/context/database.ts, src/auth/storage.ts, and src/system/artifacts.ts.

Authoritative source context

The version-1 manifest is a literal, four-source allowlist: the canonical baseline actual/resume-main/main.tex; actual/current-context/jobs/Example-Company/automated-testing-resume-info.md; actual/current-context/projects/sample-project-archive.md; and actual/current-context/projects/sample-project.md. It also binds “Sample Project” to SampleProject. The manifest rejects extra, missing, duplicate, non-allowlisted, escaping, symbolic-link, or non-regular sources.

Synchronize after changing any of those source files:

cd apps && bun run --cwd pipeline context:sync
cd apps && bun run --cwd pipeline context:sync -- --check

The first command indexes the manifest and verifies freshness; the second only reports freshness and exits nonzero when it is stale. Creating, retrying, regenerating, editing, or approving a run requires a fresh snapshot. Every stage rechecks the run’s source snapshot, so source drift cannot silently continue a claimed run.

Sources: context-sources.json, src/context/manifest.ts, scripts/context-sync.ts, src/api/run-service.ts, and src/stages/processor.ts.

OAuth onboarding and fixed models

The application owns OAuth storage and permits at most one OAuth credential per provider: openai-codex and google-antigravity. Static credentials are rejected, and provider-key and cloud-provider environment variables are scrubbed. Do not configure API keys for this system. The API reports each provider as connected or disconnected with redacted identity fields.

Start a provider session from the web UI (or the authentication API), follow the returned browser instructions or prompt, poll the session to a terminal state, and log out using the provider control when needed. OAuth sessions can be pending, succeeded, failed, cancelled, or expired.

Tailoring, analysis, edit, and repair agent
openai-codex/gpt-5.6-sol, through @openai/agents-core@0.13.2 and @oh-my-pi/pi-ai@16.4.6.
Visual inspection
google-antigravity/gemini-3.5-flash, using @oh-my-pi/pi-ai@16.4.6 and @oh-my-pi/pi-catalog@16.4.6.

Sources: package.json, src/auth/storage.ts, src/auth/service.ts, src/auth/oauth-only-resolver.ts, src/models/oauth-codex-model.ts, and src/models/gemini-inspector.ts.

Workflow, revisions, and attempts

A new run moves from queued through analyzing, tailoring, compiling, deterministic_qa, visual_qa, and review; editing is used for human-comment and regeneration revisions, and repairing is used only after one repairable compile failure. A run ends in approved or failed. The stage processor persists structured analysis, a tailoring plan, evidence ledger, rendered TeX, compilation output, deterministic QA, visual QA, and applicable edit or repair reports.

Revisions have initial, machine-regeneration, or human-comments public origins. Attempts record their stage, ordinal, state, agent session identifier, tool count, compile count, and timing. Events, artifacts, edit requests, and source snapshots are protected by database triggers against update and deletion; artifacts are finalized with SHA-256 metadata and source-artifact lineage. A failed run may be retried; human comments or layout regeneration create a new revision from a reviewable PDF.

Sources: src/contracts/index.ts, src/stages/processor.ts, src/db/migrations.ts, and src/api/run-service.ts.

Singleton claim and expiry recovery

Only one run claim exists. A claim has a 60-second lifetime and the worker heartbeats it every 20 seconds. Claim ownership includes a fresh 256-bit base64url token. If a heartbeat or release loses ownership, the worker aborts its work and schedules another acquisition after the claim lifetime.

After an expired claim, acquisition examines the interrupted active attempt. If its recorded process is still alive, it requests cancellation and waits; if the process identity is known dead, it cancels that attempt, records the event, and reclaims the runnable run. No manual database edit is the recovery procedure: restore or restart the pipeline process and let the scheduler acquire the work. Check the run timeline and attempts through the API or web UI after recovery.

Sources: src/worker/claims.ts, src/worker/scheduler.ts, and src/db/repository.ts.

Artifact security and TeX compilation

Artifact roots, run-input directories, and attempt directories must be contained, real directories; symbolic links are rejected. Directories are private (0700), writes are exclusive and private (0600), files are atomically renamed after syncing, and reads reject escaping, symbolic-link, non-regular, oversize files. Limits are: TeX 256 KiB; stdout 256 KiB; stderr 256 KiB; log 1 MiB; PDF 10 MiB; and PNG 25 MiB.

The compiler writes a trusted wrapper that requires Latin Modern and invokes latexmk with locked pdflatex, no shell escape, and a private TeX cache. Full compilation has a 120-second timeout; repair candidates have a 60-second timeout. TeX that uses forbidden primitives, shell escape, parent/absolute file access, NULs, or over-limit source is rejected. A repairable compile failure allows one repair stage per revision; its agent has a 10-minute deadline, at most 8 tool calls and 2 MiB of tool I/O, and at most 3 candidate compiles. Repair validation preserves the immutable skeleton, visible body content and order, links, inert comments, and control-sequence order.

Public artifacts are a whitelist and are exposed only for the current review revision or an approved revision. Before the response is sent as a no-store attachment, the service enforces the public size limit, rereads the stored content, and verifies its SHA-256 digest; it returns content type, content length, digest, ETag, and nosniff. Internal logs and agent transcripts are not public artifact kinds.

Sources: src/system/artifacts.ts, src/resume/compiler.ts, src/agents/repair-agent.ts, src/resume/repair.ts, and src/api/run-service.ts.

Deterministic and visual QA

Deterministic QA uses Poppler output to require parseable PDF information, an unencrypted one-page US Letter PDF, extractable text, required headings, selected evidence text, usable font output with embedded fonts, and in-page word bounds. A failing deterministic report fails the run.

Visual QA rasterizes page 1 to PNG with Poppler, then sends only that PNG to google-antigravity/gemini-3.5-flash through the OAuth-only resolver. Gemini reports pass, issue, or uncertain plus bounded findings for clipping, overlap, readability, glyphs, spacing, and layout. Any result other than pass requires a human visual acknowledgement before approval.

Sources: src/resume/deterministic-qa.ts, src/resume/rasterize.ts, src/models/gemini-inspector.ts, and src/stages/processor.ts.

HTTP API and preconditions

All routes are under /v1. JSON responses are no-store. Every mutation requires an Origin exactly equal to the configured web origin and, when it has a body, Content-Type: application/json; otherwise it receives ORIGIN_REJECTED (403) or JSON_REQUIRED (415). Invalid JSON is INVALID_JSON (400), unrecognized routes are NOT_FOUND (404), and route-level unexpected failures are INTERNAL_ERROR (500).

GET /v1/health
Returns {"status":"ok"}.
GET /v1/context
Returns bounded freshness, manifest-match, missing/stale source, and index summary fields.
POST /v1/context/sync
Requires {}; returns synchronized context status, or INVALID_REQUEST (400) / CONTEXT_SYNC_FAILED (500).
GET /v1/auth
Returns both provider statuses.
POST /v1/auth/{provider}/sessions
Requires {}; starts OAuth onboarding and returns 201. Starting an already-connected provider is AUTH_ALREADY_CONNECTED (409); a second active sign-in for the provider is AUTH_CONFLICT (409).
GET, DELETE /v1/auth/sessions/{sessionId}
Reads or cancels a session; an unknown session is AUTH_SESSION_NOT_FOUND (404), and cancelling a finished session is SESSION_TERMINAL (409).
POST /v1/auth/sessions/{sessionId}/prompt
Accepts {"value":"…"}. The route schema accepts 1–8192 characters, while the session manager rejects values above 4,096 as INVALID_PROMPT (400); answering when no prompt is pending is INVALID_PROMPT (409), and an unknown session is SESSION_NOT_FOUND (404).
DELETE /v1/auth/{provider}
Logs the provider out and returns 204.
GET /v1/runs, GET /v1/runs/{runId}
Lists or retrieves the public run view; a missing run is RUN_NOT_FOUND (404).
POST /v1/runs
Accepts {"jobDescription":"…"} containing 40–50,000 trimmed characters and returns 201; invalid input is INVALID_REQUEST (400).
POST /v1/runs/{runId}/retry
Requires {}.
POST /v1/runs/{runId}/regenerate
Requires {"expectedPdfSha256":"64 lowercase hex characters"}.
POST /v1/runs/{runId}/edit
Requires 1–8,000 trimmed comment characters and the expected PDF hash.
POST /v1/runs/{runId}/approve
Requires the expected PDF hash and optional acknowledgeVisualIssues.
GET /v1/runs/{runId}/artifacts/{artifactId}
Downloads only an eligible public artifact; missing or ineligible artifacts are ARTIFACT_NOT_FOUND (404), and content/metadata integrity failures are ARTIFACT_CORRUPT (409).

Run mutations first require fresh context (CONTEXT_STALE, 409). A changed source snapshot yields SOURCE_DRIFT (409); an outdated expected hash yields STALE_PDF (409); unacknowledged non-pass visual QA yields VISUAL_ACKNOWLEDGEMENT_REQUIRED (409); an active claim yields RUN_CLAIMED (409); other state-precondition conflicts are RUN_CONFLICT (409). Invalid mutation payloads return INVALID_REQUEST (400).

Authentication errors are returned as their service code and status, while malformed authentication route payloads are INVALID_REQUEST (400). Context-status loading failure is CONTEXT_STATUS_FAILED (500).

Sources: src/api/handler.ts, src/api/context-routes.ts, src/api/auth-routes.ts, src/api/run-routes.ts, src/api/run-service.ts, src/auth/service.ts, src/auth/sessions.ts, and src/contracts/index.ts.

Troubleshooting and verification

cd apps && bun run --cwd pipeline doctor
cd apps && bun run --cwd pipeline context:sync -- --check
cd apps && bun run --cwd pipeline context:sync

The doctor emits JSON. Its checks are ok, warning, or error; only errors make ok false and produce exit code 1. Therefore disconnected OAuth is reported as the auth_absent warning, and expired OAuth as auth_expired; neither is a doctor failure by itself. Connect or refresh OAuth before a workflow needs that provider. Resolve stale_index with the sync command. The doctor classifies unavailable Bun, LaTeX, or Poppler commands as missing_system_tool, and invalid context or descriptor configuration as errors.

Sources: scripts/doctor.ts, src/system/doctor.ts, and scripts/context-sync.ts.
