Configuration and data stores

The package is @jobhunter/pipeline. Its scripts are dev, build, start, typecheck, test, context:sync, and doctor. The API listens only on 127.0.0.1:3457; its default allowed mutation origin is http://127.0.0.1:3456, overridable with JOBHUNTER_WEB_ORIGIN.

Three SQLite databases are deliberately separate: pipeline state at apps/pipeline/data/state/pipeline.sqlite, context index at apps/pipeline/data/context/context.sqlite, and OAuth storage at apps/pipeline/data/oauth/auth.sqlite. The state and context databases use WAL, foreign keys, and a 5-second busy timeout. Context and OAuth directories are created with mode 0700; the context and OAuth database files are set to 0600. Run inputs and attempt artifacts are stored beneath apps/pipeline/data/runs.

Run files are retained separately from SQLite history. After the single worker reaches an idle drain, retention keeps the ten newest persisted runs by runs.queue_sequence, the creation-order sequence; it does not use UUIDs, timestamps, approval time, or application status. An older queued or active run, a currently claimed run, or one with a running or cancellation-requested attempt is temporarily protected. Once such a run is inactive, a later idle drain can prune it, so apps/pipeline/data/runs can temporarily contain more than ten run directories.

Authoritative source context

The version-1 manifest is a literal, four-source allowlist: the canonical baseline actual/resume-main/main.tex; actual/current-context/jobs/Example-Company/automated-testing-resume-info.md; actual/current-context/projects/sample-project-archive.md; and actual/current-context/projects/sample-project.md. It also binds “Sample Project” to SampleProject. The manifest rejects extra, missing, duplicate, non-allowlisted, escaping, symbolic-link, or non-regular sources.

Synchronize after changing any of those source files:

cd apps && bun run --cwd pipeline context:sync
cd apps && bun run --cwd pipeline context:sync -- --check

The first command indexes the manifest and verifies freshness; the second only reports freshness and exits nonzero when it is stale. Creating, retrying, regenerating, editing, or approving a run requires a fresh snapshot. Every stage rechecks the run’s source snapshot, so source drift cannot silently continue a claimed run.

OAuth onboarding and fixed models

The application owns OAuth storage and permits at most one OAuth credential for each of two providers: openai-codex and google-antigravity. Static credentials are rejected, and provider-key and cloud-provider environment variables are scrubbed. Do not configure API keys for this system. The API reports each provider as connected or disconnected with redacted identity fields. At startup, the local auth store hard-deletes every persisted credential for a provider outside that two-provider allowlist, including active and disabled rows and their related credential-block and refresh-lease rows; it enables secure deletion and checks SQLite WAL truncation before normal auth storage opens.

Start a provider session from the web UI (or the authentication API), follow the returned browser instructions or prompt, poll the session to a terminal state, and log out using the provider control when needed. OAuth sessions can be pending, succeeded, failed, cancelled, or expired.

Tailoring, analysis, edit, and repair agent
openai-codex/gpt-5.6-sol, through @openai/agents-core@0.13.2 and @oh-my-pi/pi-ai@16.4.6.
Visual inspection
google-antigravity/gemini-3.5-flash, using @oh-my-pi/pi-ai@16.4.6 and @oh-my-pi/pi-catalog@16.4.6.
Job-posting extraction fallback
openai-codex/gpt-5.6-luna through the OAuth-only resolver and the OpenAI Codex OAuth connection. It uses high reasoning, whose wire model ID remains the unchanged dotted gpt-5.6-luna; extraction has a 120-second deadline, rejects a model response above 64 KiB, and has no application-owned retry loop or caller output-token cap. OpenAI Codex is needed only when deterministic job-source extraction falls through to this model.

Internal browser-harness OAuth/model bridge

The pipeline owns Provider access, OAuth storage, refresh, logout, and the fixed openai-codex/gpt-5.6-sol model path. The local Browser Use harness does not receive a provider API key or open the OAuth database; it can request inference only through the pipeline’s exact internal GET and POST /v1/internal/browser-harness/codex bridge.

When JOBHUNTER_HARNESS_TOKEN is set to at least 32 characters, the loopback pipeline exposes the bearer-protected bridge. When the token is unset, that exact path returns 404 NOT_FOUND. The bridge requires the same bearer token, checks the application-owned openai-codex OAuth connection, and returns fixed model metadata for openai-codex/gpt-5.6-sol at high reasoning. It is routed before the public mutation-Origin policy, but is not a public browser API, adds no CORS behavior, and accepts no other path through that boundary.

POST requests must be JSON, remain at or below 4 MiB, and carry a UUID session ID, a system prompt of at most 1 MiB UTF-8, a transcript of at most 3 MiB UTF-8, and optionally a strict object output schema. The 300-second deadline covers both request consumption and model resolution. The service disables model storage, tracing, retries, and parallel tool calls; it returns fixed errors rather than provider details. Configure the token only through the trusted local environment; do not expose it to browser code or use provider API keys.

For the loopback harness’s shared-bearer setup, session/SSE lifecycle, upload limits, exact-origin controls, Chrome/WSL operation, privacy boundaries, human handoff, and focused verification commands, see Browser harness application operations. Workflow, revisions, and attempts

A new run moves from queued through analyzing, tailoring, compiling, deterministic_qa, visual_qa, and review; editing is used for human-comment and regeneration revisions, and repairing is used only after one repairable compile failure. A run ends in approved or failed. The stage processor persists structured analysis, a tailoring plan, evidence ledger, rendered TeX, compilation output, deterministic QA, visual QA, and applicable edit or repair reports.

Revisions have initial, machine-regeneration, or human-comments public origins. Attempts record their stage, ordinal, state, agent session identifier, tool count, compile count, and timing. Events, artifacts, edit requests, and source snapshots are protected by database triggers against update and deletion; artifacts are finalized with SHA-256 metadata and source-artifact lineage. A failed run may be retried; human comments or layout regeneration create a new revision from a reviewable PDF.

When an inactive review, approved, or failed run falls outside that newest-ten creation-order window, retention permanently removes its run directory. The SQLite run, revision, attempt, event, artifact metadata, and source-snapshot history remains visible and immutable; only the filesystem artifacts are removed. A durable pruning reservation prevents a partially removed directory from being reused.

Independent application lifecycle

Every public RunDto requires applicationStatus. Its values are applied, rejected, interview, accepted, and failed; a new run starts as applied. This user-managed lifecycle is independent of the required pipeline execution status, whose values continue to describe queued work, stages, review, approval, or execution failure. In particular, application failed and pipeline failed are separate values.

Pipeline schema version 3 retains version 2’s non-null runs.application_status column with an applied default and a check limited to those five values, and adds the run_artifact_retention reservation table. A retention row records a selected run as pruning or pruned, with selection and terminal-pruning times. The migration routine performs outstanding schema changes, migration records, and the schema-version update in one immediate transaction. A migration error rolls that transaction back, so a version-1 or version-2 database remains at its prior schema version and migration records instead of being recreated or partially advanced.

Updating the application lifecycle changes only applicationStatus and, when the value differs, updatedAt. Repeating the current value is idempotent. The update does not change execution status, revisions, claims, scheduler state, or the pipeline timeline, and remains allowed after artifact pruning because it does not read filesystem artifacts.

Sources: src/contracts/index.ts, src/db/migrations.ts, src/db/repository.ts, src/api/run-service.ts, and src/api/run-routes.ts.

Singleton claim and expiry recovery

Only one run claim exists. A claim has a 60-second lifetime and the worker heartbeats it every 20 seconds. Claim ownership includes a fresh 256-bit base64url token. If a heartbeat or release loses ownership, the worker aborts its work and schedules another acquisition after the claim lifetime.

After an expired claim, acquisition examines the interrupted active attempt. If its recorded process is still alive, it requests cancellation and waits; if the process identity is known dead, it cancels that attempt, records the event, and reclaims the runnable run. No manual database edit is the recovery procedure: restore or restart the pipeline process and let the scheduler acquire the work. Check the run timeline and attempts through the API or web UI after recovery.

Sources: src/worker/claims.ts, src/worker/scheduler.ts, and src/db/repository.ts.

Artifact security and TeX compilation

Artifact roots, run-input directories, and attempt directories must be contained, real directories; symbolic links are rejected. Directories are private (0700), writes are exclusive and private (0600), files are atomically renamed after syncing, and reads reject escaping, symbolic-link, non-regular, oversize files. Limits are: TeX 256 KiB; stdout 256 KiB; stderr 256 KiB; log 1 MiB; PDF 10 MiB; and PNG 25 MiB.

The compiler writes a trusted wrapper that requires Latin Modern and invokes latexmk with locked pdflatex, no shell escape, and a private TeX cache. Full compilation has a 120-second timeout; repair candidates have a 60-second timeout. TeX that uses forbidden primitives, shell escape, parent/absolute file access, NULs, or over-limit source is rejected. A repairable compile failure allows one repair stage per revision; its agent has a 10-minute deadline, at most 8 tool calls and 2 MiB of tool I/O, and at most 3 candidate compiles. Repair validation preserves the immutable skeleton, visible body content and order, links, inert comments, and control-sequence order.

Public artifacts are a whitelist and are exposed only for the current review revision or an approved revision while that run’s artifacts are retained; approval does not make artifacts downloadable indefinitely. Before the response is sent as a no-store attachment, the service enforces the public size limit, rereads the stored content, and verifies its SHA-256 digest; it returns content type, content length, digest, ETag, and nosniff. Internal logs and agent transcripts are not public artifact kinds. Retention removes only the explicitly selected, validated real run directory, never unknown sibling directories.

Sources: src/system/artifacts.ts, src/resume/compiler.ts, src/agents/repair-agent.ts, src/resume/repair.ts, and src/api/run-service.ts.

Deterministic and visual QA

Deterministic QA uses Poppler output to require parseable PDF information, an unencrypted one-page US Letter PDF, extractable text, required headings, selected evidence text, usable font output with embedded fonts, and in-page word bounds. A failing deterministic report fails the run.

Visual QA rasterizes page 1 to PNG with Poppler, then sends only that PNG to google-antigravity/gemini-3.5-flash through the OAuth-only resolver. Gemini reports pass, issue, or uncertain plus bounded findings for clipping, overlap, readability, glyphs, spacing, and layout. Any result other than pass requires a human visual acknowledgement before approval.

Sources: src/resume/deterministic-qa.ts, src/resume/rasterize.ts, src/models/gemini-inspector.ts, and src/stages/processor.ts.

HTTP API and preconditions

All routes are under /v1. JSON responses are no-store. Except for the separately authenticated internal browser-harness bridge documented above, every mutation requires an Origin exactly equal to the configured web origin and, when it has a body, Content-Type: application/json; otherwise it receives ORIGIN_REJECTED (403) or JSON_REQUIRED (415). Invalid JSON is INVALID_JSON (400), unrecognized routes are NOT_FOUND (404), and route-level unexpected failures are INTERNAL_ERROR (500).

GET /v1/health
Returns {"status":"ok"}.
GET /v1/context
Returns bounded freshness, manifest-match, missing/stale source, and index summary fields.
POST /v1/context/sync
Requires {}; returns synchronized context status, or INVALID_REQUEST (400) / CONTEXT_SYNC_FAILED (500).
GET /v1/auth
Returns the two provider statuses in OpenAI Codex and Google Antigravity order.
POST /v1/auth/{provider}/sessions
Requires {}; starts OAuth onboarding and returns 201. Starting an already-connected provider is AUTH_ALREADY_CONNECTED (409); a second active sign-in for the provider is AUTH_CONFLICT (409).
GET, DELETE /v1/auth/sessions/{sessionId}
Reads or cancels a session; an unknown session is AUTH_SESSION_NOT_FOUND (404), and cancelling a finished session is SESSION_TERMINAL (409).
POST /v1/auth/sessions/{sessionId}/prompt
Accepts {"value":"…"}. The route schema accepts 1–8192 characters, while the session manager rejects values above 4,096 as INVALID_PROMPT (400); answering when no prompt is pending is INVALID_PROMPT (409), and an unknown session is SESSION_NOT_FOUND (404).
DELETE /v1/auth/{provider}
Logs the provider out and returns 204.
GET /v1/runs, GET /v1/runs/{runId}
Lists or retrieves the public run view; a missing run is RUN_NOT_FOUND (404). For a run with a pruning reservation or permanently pruned files, the RunDto still includes status, application status, current revision, attempts, and timeline, but has an empty artifacts list and omits currentPdfSha256.
PATCH /v1/runs/{runId}
Requires the strict JSON object {"applicationStatus":"applied|rejected|interview|accepted|failed"}, updates only the independent application lifecycle, and returns the updated RunDto without waking the scheduler. It remains available after artifact pruning. Missing, extra, or unrecognized request fields return INVALID_REQUEST (400); an unknown run returns RUN_NOT_FOUND (404).
POST /v1/runs
Requires exactly {"jobUrl":"…"}. The value is a trimmed absolute HTTP(S) URL without embedded credentials; fragments are removed before use, the canonical value is used, and both entered and canonical URLs are limited to 2,048 characters. The route returns a RunDto with status 201 only after server-side ingestion produces a final 40–50,000-character description. Missing, extra, malformed, unsupported-scheme, credentials-bearing, or over-limit request fields return INVALID_REQUEST (400), Job URL must be a valid HTTP(S) URL.
POST /v1/runs/{runId}/retry
Requires {}.
POST /v1/runs/{runId}/regenerate
Requires {"expectedPdfSha256":"64 lowercase hex characters"}.
POST /v1/runs/{runId}/edit
Requires 1–8,000 trimmed comment characters and the expected PDF hash.
POST /v1/runs/{runId}/approve
Requires the expected PDF hash and optional acknowledgeVisualIssues.
GET /v1/runs/{runId}/artifacts/{artifactId}
Downloads only an eligible public artifact; missing or ineligible artifacts are ARTIFACT_NOT_FOUND (404), and content/metadata integrity failures are ARTIFACT_CORRUPT (409). A pruning or pruned run returns RUN_ARTIFACTS_PRUNED (410).

For a run with a pruning reservation or permanently pruned files, artifact downloads and the retry, regenerate, edit, and approve commands return RUN_ARTIFACTS_PRUNED (410), Run artifacts were removed by the ten-run retention policy. This is a permanent artifact-state result, not an invitation to recreate or retry the removed files.

Job-source ingestion and public failures

The pipeline fetches the canonical URL itself; it does not trust browser-fetched content. Before every request and redirect it permits only public HTTP(S) destinations, pins the connection to validated DNS results, follows at most five accepted redirects within one 10-second network deadline, requests identity-encoded text/html, application/xhtml+xml, or text/plain, and rejects a response body above 1 MiB. Plain text and a unique valid schema.org JobPosting JSON-LD description are deterministic paths. HTML candidates are normalized and sanitized first; when deterministic HTML selection is absent or ambiguous, the service removes non-content/hidden elements and presents static sanitized lines from main, article, or body to Luna.

The fallback source is limited to 512 KiB UTF-8 and 20,000 lines. Luna receives line-numbered inert data, returns strict inclusive line ranges (at most 100), and the service reconstructs text only from the original sanitized lines. It rejects a model response above 64 KiB and revalidates the reconstructed description at 40–50,000 characters. Raw HTML, fetched source URLs, selected ranges, and model-generated prose/transcripts are never persisted or exposed in RunDto; after final validation, only the immutable job-description.txt text is stored for the existing tailoring pipeline.

Run creation, retry, regeneration, editing, and approval first require fresh context (CONTEXT_STALE, 409). A changed source snapshot yields SOURCE_DRIFT (409); an outdated expected hash yields STALE_PDF (409); unacknowledged non-pass visual QA yields VISUAL_ACKNOWLEDGEMENT_REQUIRED (409); an active claim yields RUN_CLAIMED (409); other state-precondition conflicts are RUN_CONFLICT (409). For a pruning or pruned run, retry, regeneration, editing, and approval instead return RUN_ARTIFACTS_PRUNED (410). Invalid mutation payloads return INVALID_REQUEST (400).

Authentication errors are returned as their service code and status, while malformed authentication route payloads are INVALID_REQUEST (400). Context-status loading failure is CONTEXT_STATUS_FAILED (500).

Troubleshooting and verification

cd apps && bun run --cwd pipeline doctor
cd apps && bun run --cwd pipeline context:sync -- --check
cd apps && bun run --cwd pipeline context:sync

The doctor emits JSON. Its checks are ok, warning, or error; only errors make ok false and produce exit code 1. It checks the two OAuth providers and three fixed model descriptors: openai-codex/gpt-5.6-sol, google-antigravity/gemini-3.5-flash, and openai-codex/gpt-5.6-luna. The Luna descriptor is checked under model-luna, and high reasoning resolves to the unchanged dotted gpt-5.6-luna model ID. Disconnected OAuth is reported as the auth_absent warning, and expired OAuth as auth_expired; neither is a doctor failure by itself. Connect or refresh the specific provider before a workflow needs it: OpenAI Codex is required only for a job page that reaches Luna fallback extraction. Resolve stale_index with the sync command. The doctor classifies unavailable Bun, LaTeX, or Poppler commands as missing_tool; a malformed or unavailable fixed descriptor as model_descriptor_invalid; a failed entitlement probe as model_probe_failed; and a malformed auth store as auth_configuration_invalid.

For an initialization failure, use the fixed public code, status, and message listed in HTTP API and preconditions; do not infer network, DNS, parser, OAuth credential, or model details from the response. Sources: scripts/doctor.ts, src/system/doctor.ts, src/api/job-source.ts, src/api/run-service.ts, and scripts/context-sync.ts.
