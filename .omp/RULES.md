# Documentation rules

Before making any repository change, you MUST read the relevant documentation under `info/docs/` so the change follows the documented behavior and conventions. After making a change, you MUST update every affected documentation page so the documentation remains accurate.

Documentation is written as plain, semantic HTML with a short overview, simple navigation, and clearly named sections for each feature or operational topic. The prose is precise and implementation-focused, covering behavior, boundaries, constraints, failure states, and concrete commands with inline code, lists, tables, or command blocks as needed. Claims link directly to their source files, while troubleshooting guidance and cross-links connect each page to the rest of the system.
